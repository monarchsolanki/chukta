# ADR-0017: A human-written Hinglish set, generation by a different model family, and metrics split by source

| | |
|---|---|
| **Purpose** | Records where evaluation data comes from and how results are reported, so synthetic scores cannot flatter the system. |
| **Intended reader** | Anyone building the golden set, running evals or reporting metrics. |
| **Doc status** | In Review |
| **Decision status** | Accepted, 2026-09-11 (checkpoint 1). Modified: the owner and 2 or 3 contributors write 80 messages, and no blended number is ever reported. Amended at step 4 by ADR-0034 (2026-09-12). |
| **Related** | PRD §10.1, SM-13, SM-14 |

## Context

v1's golden set is synthetic. If the same model family generates the buyer messages and also classifies them, scores inflate, because the two share style and blind spots. LLM-written Hinglish is also too clean compared with real WhatsApp text.

## Decision

- **Four sources,** always reported separately: G (generated), H (human-written), A (adversarial) and R (hand-computed reference).
- **G is generated by a different model family** from the one that classifies. The classifier family is fixed before generation starts, and every generated item records its generating model.
- **H is 80 messages** written by the owner and 2 or 3 other contributors, for stylistic variance, plus hand-built ledgers and dispute cases. Each message is labelled by its writer and checked by a second contributor. Disagreements are resolved and recorded.
- **H is split into dev and test portions** (the split is set in `05`). The test portion is never used for prompt tuning.
- **No blended number is ever reported.** Every H figure is shown with its label counts and a bootstrap 95% interval.

## Alternatives rejected

| Alternative | Why rejected |
|---|---|
| Generate with the same model family | Inflated scores |
| One blended headline number | Hides the gap between sources, which is exactly what we most need to see |
| Crowd-sourced Hinglish | Cost and quality control. 80 owner-sourced messages are enough for v1. |

## Consequences

- H is small, so its intervals are wide. Targets on H are met by the point estimate, with the interval always shown.
- The generation pipeline stores provenance per item.
- Publishing a blended number is logged as a defect in the bug register.
